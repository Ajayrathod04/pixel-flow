PIXELFLOW ACCELERATOR ARCHITECTURE

Image File → Memory Initialization → FPGA Convolution → Reconstructed Image

PixelFlow converts raw image data into an FPGA-compatible hexadecimal memory file, streams it into a SystemVerilog 2D separable convolution hardware accelerator using Vivado XSim, captures hardware output MEM data, and reconstructs the filtered image via Python.

HOW PIXELFLOW WORKS — STEP-BY-STEP FLOW

1
INPUT IMAGE
Normal image in PNG, JPG, or BMP format loaded into workspace.
2
GRAYSCALE & RESIZE
prepare_image.py resizes image to 32×32 and converts to 8-bit grayscale.
3
HEX MEMORY
1024 8-bit hex bytes written to input.mem in row-major order.
4
$readmemh
SystemVerilog testbench loads input.mem into simulation RAM array.
5
ROW CONVOLUTION
row_convolver.sv applies horizontal 1D FIR kernel [1 2 1].
6
COLUMN CONVOLUTION
column_convolver.sv applies vertical 1D FIR kernel [1 2 1]ᵀ.
7
NORMALIZATION
Filtered 16-bit values shifted right by 4 (>>> 4, divide by 16) to 8-bit.
8
OUTPUT MEM
Filtered hardware pixels captured to output.mem file.
9
MEM → PNG
reconstruct.py reads output.mem and saves final reconstructed PNG.

How does the image enter hardware?

input.mem

image_mem[0:1023]
➔ row_in ➔

The Python script prepare_image.py creates the input.mem text file. In the SystemVerilog testbench (tb_image_filter.sv), the $readmemh System Task loads those hexadecimal pixel values into simulation memory: 

initial begin
    $readmemh(INPUT_MEM, image_mem);
end

The testbench then streams 2 rows per clock cycle over 512-bit wide memory buses directly into the image_filter_top hardware module.

By decoupling 2D convolution into two 1D stages, PixelFlow reduces multiply-accumulate complexity from O(K × L) to O(K + L) per pixel, allowing 2 rows/cycle parallel hardware throughput!
